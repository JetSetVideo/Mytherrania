## What changed

- **Stage scrubber** (`src/ui/GenStages.ts`, markup in the + New column under the viewer plate): a radio group of the
  pipeline's seven stages (`GEN_STAGE_IDS` is pinned equal to P's `Pipeline.STAGE_IDS`), 1 Skeleton · 2 Cage · 3 Inflate ·
  4 Carve · 5 Skin · 6 Hitboxes · 7 Paint; a grid of ≥ 44 px buttons that wraps (2 rows ≥ 390 px, 3 rows at 320 px); click,
  arrows, Home/End. The readout under it shows the stage's wall time (`of` the pipeline total) and its key metrics from
  the `StageRecord` (key metrics first per stage, `KEY_METRICS`), plus warnings.
- **Stage views** (`PreviewScene.buildStageView`, pure geometry): Skeleton = K's `tPoseBones`/`tPoseDisks` (gold bones, joint
  beads, blue cross-section rings, T-pose); Cage = P's cage parts as cyan wire boxes over a ghost body; Inflate = B's
  `skinInflated` polygonised (volumes before carving); Carve = the carved skin + every sculpt stroke's centre (violet);
  Skin = the polygon skin coloured by its dominant skin-weight bone + wireframe; Hitboxes = the painted bind skin + one
  translucent capsule per hitbox (hue per zone); Paint = the finished, posed rig (the pre-wave view).
- **Wiring without an Engine edit**: the Menu writes `data-gen-view` / `data-gen-stats` on the preview canvas; PreviewScene
  reads them each frame (`#syncDataset`), computes `generateStaged` only for a non-Paint stage (debounced
  `STAGED_DEBOUNCE_MS` after the last rebuild; hitboxes fitted only for the Hitboxes stage), and dispatches
  `mytherrania:gen-stages` with the records; the Menu paints the readout from that event.
- **Drag handles** (`src/ui/DragScrub.ts`): a horizontal drag on ANY stepper's value well scrubs it (Pointer Events: mouse,
  pen, touch; `touch-action: pan-y` keeps vertical page scroll on phones; threshold 4 px mouse / 8 px touch; whole band ≈ 260 px,
  3–16 px per step; Shift = 4× finer). It writes the hidden native input + `input` event, i.e. the stepper's own path, so
  arrows, keyboard and every owner's clamp keep working. While a drag runs the values and sheet follow every step and the 3D
  model rebuilds when the pointer rests 140 ms (`SCRUB_PREVIEW_REST_MS`) — a rebuild costs 0.1–0.6 s, and per-step rebuilds
  made a 14-step drag take 8.5 s (measured in the first probe run).
- **Neighbour-dependent constraints** (`src/ui/Constraints.ts`, pure): rules measured on `Proportions.proportionsFor`:
  `waist<=hips`, `waist<=shoulders` (shoulder joint + deltoid), `head~height` (skull half-width within 0.85–1.15 × the race's
  skull at its mid height: a taller body allows a relatively smaller head), `limbs~race` (arm × limbLength within 0.8–1.2 × the
  race's arm), `weight~bmi` (BMI within 0.72–1.4 × the race's mid BMI). Each rule names what it CLAMPS; an edit of a
  number it does not clamp (height) is a DRIVER and the clamped ones SETTLE (`applyEdit`). Bands come from a scan + bisection,
  so no inverse of `proportionsFor` is needed. The Creator's height/weight/silhouette steppers take these bands as their min/max.
- **0..1000 stat view** (`src/ui/StatView.ts`, beside the viewer above the sheet): Strength, Agility, Intelligence, Level from
  P's `StatScale.generatorStats(profile)`, each a stepper (0..1000, step 10, draggable) with a bar (reference tick at 500).
  **Decision: editable as a preview-only what-if.** A change rebuilds the 3D model with those stats (`BodySpec.stats`) but is
  never written to the profile — the game derives these numbers from class/race/attributes/level, so a saved hero always
  carries the stats its sheet implies. Reset (shown only while a what-if is active) returns to the fighter's own; any roll or
  edit that changes the fighter's own stats drops the what-if.
- **BodySpec.stats in the preview** (`previewBody`): the preview builds with `stats: profileBodyStats(profile)` (the Engine's own call = StatScale.generatorStats; or the what-if),
  and `previewKey` includes the stats, so an attribute tweak now rebuilds the model. `previewKey(profile)` keeps its one-argument
  signature (`profiles.map(previewKey)` in tests/portraitstudio_test.ts passes an index as a 2nd argument); the what-if key is
  `previewKeyWith`.

## Click paths (mouse; a finger does the same)

- **See a stage**: title → **Fighters** → **+ New** tab → under the viewer plate, the row **1 Skeleton … 7 Paint** → click one. The
  viewer shows that stage; the box under the row shows its time and numbers. Arrow keys move along the row. **7 Paint** = the finished fighter.
- **Scrub a number**: + New → open **Race** (the *Override by hand* fields) → press on a value (between its ‹ › arrows) and drag left/right.
  The number stops where a rule stops it (the weight at the BMI floor of the height, the hips at the waist); dragging the height drags
  the weight and head along. Arrows and the keyboard still step one at a time.
- **What if**: + New → **Generator stats 0–1000** (right of the viewer, above the sheet) → drag or step Strength/Agility/Intelligence/Level → the
  model rebuilds with those stats; **Reset** returns to the fighter's own. Saving the fighter never saves a what-if.

## Honest gaps

- **Rebuild latency**: a what-if (or any body edit) rebuilds the whole body (anatomy + polygonise + weights + paint): the rig
  rebuild medians above (~0.6 s) are the generator's cost, not the UI's; the first stage view also runs `generateStaged` (~0.55 s,
  ~0.9 s with the hitbox fit). The UI keeps drags smooth by deferring the model to the pointer's rest, so the picture lags a drag.
- **`limbs~race` has no stepper**: `silhouette.limbLength` is not read by `proportionsFor` and B will not honour it this wave (board
  Z-18: moving joints breaks the planted-foot bands), so the rule is tested in Constraints.ts but the UI shows no control without an effect.
- **`waist<=shoulders` never binds inside today's static bands** (shoulder joint + deltoid is always wider than the waist); it is kept as a
  guard and pinned by the edge test. `waist<=hips` binds for heavy builds (mountain dwarf, G72) but not for the reference human the probe
  drags, so the browser probe proves the BMI neighbour clamp and the height→weight/head settle; the waist/hips clamp is proven in Deno.
- **The head settles at every extreme height** (G74: 32/32 extreme edits nudge the head knob by ~1–2 %): the anthropometric rule is
  deliberate (a 2.1 m human may not keep a mid-height head scale); widen `HEAD_BAND` if that reads as unwanted.
- **Silhouette written on a constrained edit**: a settle of a silhouette knob writes an explicit silhouette (the race's values from
  `silhouetteOf`) onto a profile that had none, replacing the name-seeded one PreviewScene shows — same rule as wave X's steppers.
- **Stage views are bind-pose (A-pose) meshes**, not the posed rig: Hitboxes shows the capsules at their fitted (bind) place, not
  following the idle pose; the Paint stage is the live rig. The Paint readout is S's `paintStage` record (P's default paint stage,
  run in the fighter's hair/accent/garment colours).
- The Paint stage shows "Pick a stage…" until a non-Paint stage has been computed once for the current body (the staged build is
  never run on the Paint view, so the default Creator costs nothing extra).
