# Wave FALL — animation (lane A, C-ANIM)

Shove / clash, stagger, stumble, fall, lying and get-up animations driven by `AnimatorInput.fall` and
`AnimatorInput.shove` (M fills them from `Fall.ts` and the shove timeline in `Engine.#animForces`).
Absent / `null` / phase `"stand"` = today's motion, byte-identical (SPEC FALL-F30).

## Contract

```ts
// src/game/anim/FallMotion.ts (re-exported by Animator.ts)
fall?:  { phase: "stand"|"stagger"|"stumble"|"falling"|"down"|"rising"; t01: number; dir: [number, number]; pose: "back"|"front"|"side" }
shove?: { phase: "brace"|"impact"|"recoil"; t01: number; dir: [number, number]; magnitude01: number }
```

`dir` is the world xz direction the body travels (fall) / is pushed (shove). New `AnimatorOutput` fields:

| field | meaning |
|---|---|
| `rootTilt` | whole-body tilt quaternion in the heading frame; rig rotation = `Ry(yaw + yawOffset) · rootTilt · Rz(roll)` (`applyRootTilt`) |
| `rootOffsetForward` | rig origin shift along local z (like `rootOffsetLateral` along x) |
| `bodyShift` | add to body x/z right after the update: the body (physics, hitboxes, ring-out, AI) follows the fallen pose's pelvis |
| `groundBody` | 0..1: seat the skin on the floor with `settleOnFloor` (exact contact) |
| `wideLimits` | pass to `Skeleton.drive(..., wide)`: lying / kneeling windows (KO trunk window, hip flexion 1.9) |
| `fallWeight` | QA: share of the keyed pose in the output |

### Engine wiring (done by M, Z-11)

```ts
const out = animator.update(dt, input);                 // input.fall / input.shove from #animForces
f.body.x += out.bodyShift[0]; f.body.z += out.bodyShift[1]; prev.x += out.bodyShift[0]; prev.z += out.bodyShift[1];
f.skeleton.drive(out.angles, out.hipRoll, out.ankleRoll, out.toeOut, undefined, out.wideLimits);
// rig placement: position += lateral·(cos, -sin)(yawNow) + forward·(sin, cos)(yawNow);
rig.group.rotation.set(0, yawNow, roll);                // ALL three: applyRootTilt re-syncs rotation.x (M Z-21)
applyRootTilt(rig.group, out.rootTilt);                 // identity = untouched
if (out.groundBody > 0) settleOnFloor(rig, groundHeight, out.groundBody);
```

`tests/wave_fall_anim_fixture.ts drive()` is the reference implementation of this order.

## Design: keyframes + whole-body grounding + contact anchoring (not the ragdoll)

A fall here is a game state with a duration from M's law that must end in a get-up; the ragdoll
(`RagdollDriver`) is a one-way hand-over that owns the bones (ring-out / KO) and would need a pose
match back to a keyed rise. So the fall is keyed (`FallMotion.ts`, authored in world-intent segment
angles and converted to joints) and made physical by three per-frame passes in `Animator.#fallFrame`:

1. **Inertialization** (`FALL_BLEND_TIME` 0.22 s): any phase switch (incl. entering from the gait and
   M changing phase before t01 = 1) carries the last output's difference and lets it decay; the first
   fall key is the live pose (snapshot), so entering never pops. Joints are rate-limited at the blender's
   `maxJointSpeed`, the root at `FALL_ROOT_SPEED` (9 rad/s), so any clip length stays continuous.
2. **Contact anchoring**: each key loads contacts (feet, knees, hands, pelvis). A contact latches where
   it ARRIVES (load ramps at the end of a segment, unload at the start); the root moves so latched
   contacts stay put; a loaded foot outranks every other contact (the get-up never slides a planted sole).
3. **Grounding**: `Rig.bodySpheres` — the rig's own FK for 32 spheres (radii from the shoulder half-span
   w for trunk/arms/thighs, the leg length for shins) — puts the lowest sphere on the floor under it
   (the body's floor while airborne: ledge falls). `SkinnedHumanoid.settleOnFloor` then seats the real
   skin exactly (lowest vertex, linear-blend skinned, ~0.5 ms per fighter per frame, only while falling).

Sequences: falling = snapshot → buckle (stance kept) → sit/kneel → lie; down = lie + breathing;
rising = (back/side: roll over onto the front) → forearms → hands and knees (turning to face the rival)
→ kneel on one knee, lead foot planted → rise over the planted foot → guard → hand the feet and heading
to the gait (`Gait.plantAt`). Shove / stagger / stumble are layered on the gait (trunk lean + roll +
pelvis drop through the IK, arm/neck offsets on an additive layer) so the steps are the gait's own
(M moves the body; the feet re-plant).

## Open issues (honest gaps)

- **Feet scuff during the collapse** (falling phase): the first keys keep the stance but the legs are
  keyed, not IK-solved, so feet that were planted at fall entry slide 6-23 cm while the body drops
  (reaction-slide column of the fall rows in anim-measure.json). Not a pinned bound.
- **Back and side get-ups end facing away** after the roll-over; the body turns on hands and knees
  toward the rival (latched at rise start) — a rival that moves during the rise is re-faced by the
  gait's facing hold afterwards (a turning step).
- **Short rises**: before M's r3 the rising phase could be 0.44 s; such a clip hits the joint / root
  speed limits (continuity holds) and the loaded foot slid up to 83 mm. M added RISE_PHASE_MIN = 1.0 s
  (Z-14); over 1.0..1.93 s the slide is 4-18 mm (pinned <= 25 mm, F35).
- **Live sink found by V (Z-17/Z-20, front pose -380 mm)**: the engine set only rotation.y/.z each frame
  while applyRootTilt writes the quaternion (re-syncing rotation.x), so the tilt compounded. Fixed in the
  engine by M (Z-21: rotation.set(0, yaw, roll) before applyRootTilt). The engine's render-side arm
  rewrites (two-hand off-hand grip, strike ArmGuard) still run after the settle on a lying body; my Z-18
  suspicion was not the cause of the sink, but a two-handed haft can still put a hand through the floor.
- **Weapon**: the blade follows the hand grip; nothing keeps it out of the floor / body while lying.
- The sphere model differs from the skin by up to ~5 cm (bulky dwarf/ork sides); the exact contact is
  the render-side settle, so a caller that skips `settleOnFloor` sees that residual.
