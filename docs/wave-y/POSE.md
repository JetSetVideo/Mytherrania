# Wave Y lane A — pose + grip (knees out, no weapon held backward)

Numbers below are generated by code: `deno run -A tools/probe-wave-y-pose.ts --rig <json>` on a build of HEAD
(`git archive HEAD`, 6876048) and on this tree, then `--doc before.json after.json` prints the tables
(`artifacts/qa-wave-y/pose/rig-before.json`, `rig-after.json`). The rig is the REAL skinned rig posed the way each
surface poses it (`tests/wave_y_pose_fixture.ts`): the engine's frame order (Animator -> Skeleton.drive ->
rig.update -> forearm supination -> SwingDriver wrist -> gripEulerOf -> choke -> two-hand step) for idle
(pre-fight standing), guard (fight standing, guard layer 0.55), block (guard layer 1), walk (2.1 m/s, worst frame),
and the Creator preview (`buildPreviewRig` + `skeleton.update` + `rig.update`, as `PreviewScene.#render`).
Body space: +z the fighter's forward. `fwd` = forward share of the grip->tip direction (< 0 = the tip behind the
frontal plane through the grip: "held backward"), `elev` = its elevation.

## Reproduction (what the user saw)

- Engine idle / guard / block / walk: no archetype pointed backward (non-dagger worst fwd 0.28-0.82).
- **Creator preview (and the Fighters-page portraits, same `buildPreviewRig`)**: EVERY archetype and the classic
  class weapon pointed up and BACK over the shoulder: fwd −0.55..−0.56, elev 56°, tip 34-48 cm behind the grip.
  Screenshot `before-weapon-*-side.png` (figure faces screen left; the blade leans right, behind the back).
- Root cause: `PreviewScene` only calls `rig.update`; nothing sets the grip there, so the rig showed its build-time
  grip `rotation.x = −0.35` about the MOUNT's x axis (a pre-wave-V "Humanoid rest grip"): no hand mapping
  (`PalmWeapon.gripEuler`) and no forearm supination — with the forearm hanging, Rx(−0.35) tips the blade's +y
  toward −z, i.e. backward, and the handle leaves the palm. The arena never showed it because the engine
  overwrites the grip every frame.

## Fix

- `SkinnedHumanoid` option `restPose` (passed by `buildPreviewRig`, one line in `PreviewScene.ts`): until a
  caller takes the grip (`setGrip`), `update()` applies the ENGINE's carry — the same forearm supination
  (`GRIP_SUPINATION`), the same carry wrist (`Swing.gripPitchFor` at `GUARD_KEY.blade`, a reverse dagger blade
  down, a bow's limbs upright) laid across the palm inside the archetype's wrist band (`GripStance.gripRuleOf`
  band -> `PalmWeapon.gripEuler`). Opt-in on purpose: the bare rig (tests, ragdoll fixtures) keeps the plain
  Skeleton pose because the hinge-only ragdoll cannot seed from a twisted forearm (with it always on, the
  ragdoll ground test and the elbow-crease rest test failed — measured, then made opt-in).
- Knees: `src/game/anim/KneeOut.ts` (pure) + `Skeleton.legRoll.kneeOut` (rests at `KNEE_OUT_SHARE` = 3.5 % of the
  leg; `drive()` takes it as a 5th argument) + `SkinnedHumanoid.update` renders it AFTER the toe-out: each leg
  SWIVELS about its own hip->ankle line by s = asin(d / r) (d = share x leg, r = the knee's distance from the
  line; capped 0.4 rad, faded out for a straight leg), and the ankle bone is given back its planted world
  rotation. Hip and ankle are on the axis, so no sole point moves (SPEC Y25: < 0.1 mm / 0.05°). Applied when the
  Skeleton is Animator-driven (the arena) or the rig has `restPose` (the preview); not on a bare undriven rig.
- No Engine change needed (the Skeleton default carries the channel; the engine's `drive()` call keeps 4 args).

## Honest gaps

- The preview carry uses the default supination (0.6 rad); the arena solves it per rig (SwingRig.solveGripTwist),
  so an ork's preview blade stands ~3° lower than in the arena. The preview does not put the OFF hand on a
  two-handed haft (the arena's OffHand step needs the swing setup); it hangs at the side.
- The idle carry (forearm hanging) stands the blade only ~34° above horizontal, forward: the wrist band
  (HAMMER_BAND) clamps the wanted near-upright carry. Not backward; a higher idle carry needs an idle arm pose
  (out of this lane's ask).
- KO ragdoll: the ragdoll's ankle is a hinge with ±0.1 rad twist, so — like the 9° toe-out — the swivel's ankle
  counter-rotation (~12° at the engine idle) cannot be held when a KO'd body is seeded (the snap itself was not measured). Measured from
  the engine idle pose (table above): 45/50 vs 46/50 human throws settled, 49/50 vs 49/50 ork — within one throw.
  Only Animator-driven or restPose rigs carry the swivel, so the ragdoll test fixtures (bare rig) are unchanged.
- Hitboxes follow the rig's bones (`boneWorldOf`), so the thigh/shin boxes move with the knees (~3 cm), as drawn.
- Bow at idle carries like a blade (34°, forward) rather than limbs-upright; pre-existing, not backward.
