## Notes on assertion semantics

- Baseline light angle reads the CURRENT PreviewScene.ts (G had already moved it 11.6° -> 9.2° when the baseline ran); the HEAD value is 11.6°.
- Ellipsis truncation (text-overflow: ellipsis / line-clamp) is counted separately as intentional, not as clipping.
- Overlaps involving a fixed/sticky bar passing over scrolled content are excluded (counted as stickyOverlaps); an overlap counts only when one of the pair is on top at the overlap centre (elementFromPoint) and both are painted.
- Shadow pixels are read only where the canvas itself is on top (elementFromPoint), so a sticky bar or socket over the plinth is never read as floor.
- Stats recompute uses Fighter.createFighter (the engine constructor) + V's own copy of Engine.#applyTweaks + applyLevel, createResources, and the engine's castFocus/CASTER_CLASSES call; mutation control (VZ_MUTATE=1 ignores the level) gives 27/390 disagreements, so the check has teeth.
- Shadow strength cross-check (scratch wz-shadow.ts, 5 random + New rolls at 820x1180, normalised 3:4 box): HEAD on/off 0.256-0.436, G r1 0.753-0.927.
- Z-stage-fit re-stated after F r2 (pitfall 10): the user-facing need is that the + New plate fits the viewport height and shows the plinth; the 1.2-1.45 aspect band was F's own 3:4 promise, so aspect is now reported, and a separate Z-stage-floor claim (>= 8 feet-ring and rim points on top as laid out) carries the visibility requirement.
- G viewer claims are judged on a box normalised to 3:4 fully on screen, so F's layout cannot hide or fake the floor; F is judged on the as-laid box.
- Semantics correction (Z-28): elementFromPoint ignores pointer-events:none layers, so F's foot scrim over the plinth was inside the shadow samples in G-r1/F-r2 and diluted on/off; G r3 both strengthened the umbra and reframed the plinth above the scrim (footReserve). The 5-roll cross-check on r3 reads on/off 0.271-0.511.
