## Lane P-0 — `src/ui/CreatorSync.ts` (new) + `tests/creatorsync_test.ts` (new)

The two pure pieces behind the parent's Creator restructure.

```ts
/** A one-line summary of a group's CURRENT values — the "global parameter" shown on a closed header. */
export function groupSummary(groupId: string, p: CharacterProfile, race: RaceDef | null, subrace: Subrace | null): string;
/** Synchronise the dependent parameters after an edit: a skin tone moves its crease/paint/eye tones with it. */
export interface EditPatch { field: string; value: string | number | boolean | null }
export function applyEdit(p: CharacterProfile, patch: EditPatch): CharacterProfile;
/** Which parameters an edit must drag along, so a half-edited fighter cannot look broken. */
export function dependentFields(field: string): string[];
```

Requirements: `applyEdit` is total and deterministic; a colour edit moves the derived tones by a stated rule
(the same luminance/hue relation the paint stacks use — read `src/graphics/paint/`); a height/weight edit
clamps into the race's own band; `groupSummary` answers for EVERY group in the Creator's tree and is never
empty (it is what a closed header shows). Assert a summary for each group id, an edit round-trip
(`applyEdit(applyEdit(p, a), inverse)` is not required to be identity, but applying the same edit twice IS),
and that no edit can produce NaN.

**Evidence:** `deno check`, the test file's count, `deno lint`, and the printed summary line for every
Creator group for two different profiles (a rolled elf and a dwarf).

## Lane P-A — `src/graphics/shaders/Ink.ts` (new, pure) + `CelShader.ts` / `CelSkinned.ts` (edit) + `tests/ink_test.ts` (new)

The outline law, extracted so it can be unit-tested, and the manga shading equation.

```ts
/** The ink mark's strength for one surface point: 1 = full mark, 0 = none. */
export function inkStrength(o: { lightDotN: number; viewDotN: number; depth: number; isFace: boolean; materialInk: number }): number;
/** The mark's width in view units at that point (0 when suppressed). */
export function inkWidth(o: { strength: number; baseWidth: number; farFade: boolean }): number;
/** The band edges + shade tone for a manga ramp: a stated equation, few bands, a hard terminator. */
export function mangaRamp(o: { lightDotN: number; bands: number; shadeTone: number; wrap: number }): { band: number; shade: number; terminator: number };
```

Requirements: `inkStrength` falls off with BOTH angles (a surface facing the light and facing the camera is
barely marked; a silhouette edge is fully marked), is suppressed on faces below a stated threshold, and is
bounded [0,1]; `inkWidth` never exceeds a stated maximum; `mangaRamp` produces a band index in [0, bands-1]
with a hard terminator and a shade that never exceeds 1. The shaders must consume these (no second copy of the
law in GLSL — pass the constants as uniforms) and keep compiling: the engine's own shader-health snapshot
(`#graphicsSnapshot`, which reports GLSL diagnostics) must show **0 broken programs**.

**Evidence:** `deno check`, `tests/ink_test.ts` count, `deno lint`, a printed ink strength/width table across
the angle range, and the shader-health line from a real browser run (0 broken programs, or the exact log).

The builds and the muscle.

- Three explicit builds — `fit`, `bulky`, `heavy` — as a `BUILDS` table with measurable differences
  (shoulder/chest/waist/hip/high-limb radii, plus a fat-vs-muscle term), and every ancestry mapped to one
  (orks and some humans `heavy` or `bulky`, elves `fit`/`bulky` with long muscles, dwarves `bulky`).
- The geometry carries visible anatomy: pectorals, an abdominal segmentation, deltoid/biceps and quad

  section counts / radii at named heights), not a claim.

  as the user asked rather than only sculpted.

**Evidence:** `deno check`, the tests' count, the pre-existing body tests (list them, green), `deno lint`, and
a printed build table (per build: the named radii + the muscle/fat terms) plus the measured silhouette delta
between `fit` and `heavy` for one ancestry.

   all 16 ancestry nodes.
